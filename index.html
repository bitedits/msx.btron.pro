ASCII · Microsoft · 1983–1993 · 8-bit Silicon Standard

8ビットの黄金律。

1983 年、アスキーとマイクロソフトによって提唱された MSX は、メーカーの垣根を越えてハードウェアとソフトウェアの完全な互換性を実現した、歴史上類を見ない 8 ビット統一コンピュータ規格です。Z80 CPU、テキサス・インスツルメンツ社製 VDP（TMS9918A から V9938、V9958 へ進化）、ゼネラル・インスツルメント社製 PSG 音源、そして洗練されたスロット拡張機構が、単一の論理空間のもとに統合されました。ソニー、松下電器、日本ビクター、日立、ヤマハらが競い、入門機から音楽スタジオ専用機、放送局用リアルタイム映像編集ワークステーションに至る多様な機械群を生み出しました。本アーカイブは、その全シリコンレジスタ仕様、システム構造、開発環境、および遊戯ソフトウェアの工学的遺産を恒久的に記録・展示するものです。

Established in 1983 through the collaboration of ASCII and Microsoft, the MSX architecture defined an unprecedented international standard for 8-bit computing that guaranteed cross-manufacturer binary compatibility. By coupling the Zilog Z80 microprocessor with dedicated video display processors (TMS9918A, V9938, V9958), a programmable sound generator (AY-3-8910), and a structured 4-tier slot bus system, MSX separated display logic from main system memory. Across four generations—MSX1, MSX2, MSX2+, and MSX turbo R—industrial heavyweights including Sony, Panasonic, Victor (JVC), Hitachi, and Yamaha expanded the platform from accessible consumer consoles to broadcast-quality video editing workstations. This portal serves as a rigorous technical repository preserving register-level documentation, development toolchains, emulation cores, and software teardowns.

00 / Architecture

第零部：スロット機構とバス分離の幾何学

Slot Expansion Matrix · VDP Memory Decoupling · Bus Arbitration

MSX の中核を成すのは、64 KiB の Z80 アドレス空間を 16 KiB 単位の 4 ページに分割し、4 つの基本スロットと各スロット配下の 4 つの拡張スロット（計 16 スロット・理論上最大 256 スロット）を動的に割り当てるスロット機構です。CPU は VRAM に直接アドレスバスを接続せず、VDP の I/O ポート（0x98–0x9B）を介して非同期に読み書きを行うことで、バスの競合を完全に排除しました。この設計こそが、全メーカーの実機でカートリッジを無変更稼働させる堅牢性の源泉泉です。

At the core of the MSX architecture lies a segmented memory management model dividing the 64 KiB Z80 addressing space into four 16 KiB pages. Primary slots are selected via the 8255 PPI port 0xA8, while secondary slots are multiplexed through memory address 0xFFFF. The VRAM is fully decoupled from the CPU bus, accessed strictly through dedicated VDP I/O ports. This hardware abstraction enabled universal software interchangeability across disparate chassis designs.

Architecture — Silicon Rules

スロット多重化と I/O 境界

スロット制御はインテル 8255 PPI のポート 0xA8 と、各拡張スロットの 0xFFFF に配置された反転レジスタによって行われます。メイン RAM は最上位のページ 3 に確保され、システム変数・フック領域（$F380–$FFFF）が常に CPU から直接参照可能となるよう配慮されています。

  • 基本スロット選択PPI ポート 0xA8（読出・書込両用）
  • 拡張スロット選択各スロットのアドレス 0xFFFF（反転書込・読出）
  • メモリマッパーポート 0xFC–0xFF による 16 KiB 物理 RAM 割当
  • VDP 制御ポートポート 0x98（データ） / 0x99（コマンド・レジスタ指定）

01 / Computers

第一部：計算機と工業意匠の頂点

Sony · Victor · Yamaha · Panasonic · Hitachi · 13 Representative Models

MSX は家庭用パーソナルコンピュータにとどまらず、各社が誇る専門領域の最先端技術を注入した実験場でもありました。ソニーは放送用編集卓とゲンロックを備えた HB-F900/G900AP を送り出し、日本ビクターは二重 CPU 構成のビデオタイトラー HC-90/95 を開発。ヤマハは本格 FM 音源モジュールと MIDI を組み込んだ YIS-805 を、松下電器はワープロと高速モデムを凝縮した FS-A1FM を世に問いました。本資料館では厳選された 13 機種のレジスタ単位の完全なハードウェア仕様を保管します。

MSX manifested across an extraordinary variety of specialized chassis. Sony produced the broadcast-oriented HB-F900 and HB-G900AP with genlock and digitizer hardware; Victor engineered dual-CPU video titlers (HC-90 and HC-95 series) for video production studios; Yamaha built the professional YIS-805 music computer with SFG-05 FM synthesis and MIDI; and Panasonic mastered integration with the FS-A1FM featuring integrated MSX-MUSIC and telecommunication modems.

02 / Systems

第二部：基盤ソフトウェアとオペレーティングシステム

MSX-BIOS · MSX-DOS · Nextor · C-BIOS · UZIX · 8-bit BTRON

MSX のソフトウェア環境は、ROM に焼き付けられた静的な BIOS だけではありません。CP/M 互換性を保ちながら MS-DOS FAT12 ファイルシステムを導入した MSX-DOS 1/2、その現代的発展形である Nextor、オープンソースの C-BIOS、UNIX V7 クローンの UZIX、そして BTRON の実身仮身モデルと超漢字思想を 8 ビット Z80 空間に凝縮した 8-bit BTRON for MSX まで、多彩なシステムが花開きました。

System software on MSX spans standard ROM BIOS vectors, CP/M-compatible MSX-DOS 1/2 with FAT12 disk structures, Albert Beevendorp's Nextor FAT16 evolution, the cleanroom open-source C-BIOS, the preemptive UNIX V7 clone UZIX, and the 8-bit BTRON subset implementing Real/Virtual body hypertext databuses on banked Z80 memory.

Firmware & Kernel Architecture

BIOS 規約と 8-bit BTRON

MSX-BIOS はスロット間インターフェース `CALSLT` ($001C) を通じて任意のページ・スロットへジャンプし、状態を安全に復帰させます。B-System における 8-bit BTRON は、このスロット機構とメモリマッパーを駆使し、Z80 上でウィンドウフレーム描画と実身仮身ハイパーテキストを実現しています。

04 / Development

第四部：現代の開発環境とクロスツール

SDCC · Pasmo · Calling Conventions · crt0 · Bank Switching

MSX 向けプログラミングは、実機上の BASIC やアセンブラから、現代の PC 上での高度なクロスコンパイラ環境へと進化しました。中核を担う SDCC（Small Device C Compiler）は、レジスタ呼出規約 `__sdcccall(1)` による高速な Z80 コード生成を実現。Pasmo による直截なアセンブリと組み合わせることで、ROM カートリッジから MSX-DOS 実行ファイルまで、堅牢な C99/C89 開発が可能です。

Cross-development for MSX centers around modern ANSI C compilers and fixed-address assemblers. SDCC provides aggressive peephole optimization and register-based parameter passing via __sdcccall(1), while Pasmo delivers instantaneous multi-target assembly producing raw ROM images, MSX-DOS .COM binaries, and BLOAD files with automated debugger symbol generation.

Development Toolchains

SDCC と Pasmo の黄金律

標準 C ランタイムを排除し、独自の `crt0_msx.asm` によってカートリッジ識別子 `$4142`（"AB"）と初期化ルーチンを注入。VDP ポート叩きをインラインアセンブラで記述することで、実機 3.58 MHz の限界性能を引き出します。

05 / Emulators

第五部：エミュレーション基盤とデバッガ

openMSX · blueMSX · tronMSX · Cycle-Accurate Validation

MSX エミュレータは、過去の遺産を再現するだけでなく、現代のソフトウェア開発における不可欠の検証基盤です。オープンソース界で最も厳密なサイクル精度と Tcl 遠隔制御を誇る openMSX、洗練された GUI とマシンエディタを備えた blueMSX、そして B-System 内部に C99 純実装として組み込まれた確定性コア tronMSX。三つの基盤が開発者の足元を支えます。

Emulation serves as the bedrock for modern MSX verification. openMSX establishes the reference standard with cycle-accurate VDP renderers, time-travel reverse debugging, and Tcl pipe automation. blueMSX offers dynamic slot-configuration editing and BiFi trace hooks. tronMSX embeds an uncompromising cleanroom C99 MSX2+ core inside B-System according to NASA/JPL Power of Ten reliability rules.
