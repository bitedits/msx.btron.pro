UZIX (Systems)

8 ビット MSX 上で稼働する、プロセス仮想メモリとプリエンプティブマルチタスクを備えた本格 Unix V7 クローン。 "Complete technical specification of UZIX, a true Unix Seventh Edition clone running on Z80 MSX hardware utilizing memory mappers for per-process memory virtualization."
← 基本ソフト目録へ戻る (Systems Index)
Z80 上の真の UNIX とメモリマッパーのプロセス分離 — UZIX は、PC 向け Unix V7 の設計を MSX Z80 へ移植したオペレーティングシステムです。ハードウェア MMU を持たない Z80 において、MSX の標準メモリマッパー（16 KiB セグメント）をプロセス空間切り替え機構として活用。プロセスごとに独立した 32 KiB のユーザ空間を提供し、タイマー割り込みによるプリエンプティブスケジューリング、fork/exec、Unix パイプ、および標準シェル（sh）を実現しました。B-System の B-MSX では、メモリマッパーポート 0xFC–0xFF の完全エミュレーションにより、UZIX のマルチタスク実行を完全サポートします。
"UZIX demonstrates the surprising sophistication of MSX hardware by deploying a preemptive Unix V7 kernel onto banked Z80 architecture. By multiplexing memory mapper segments to serve as virtual address spaces, it provides true process isolation, pipe IPC, and a standard Unix userland. Within B-System, the B-MSX core accurately models mapper I/O ports $FC–$FF to host preemptive UZIX processes."
01 / Kernel Memory

1. カーネルメモリ構造とプロセス空間分離 (Kernel Memory Layout)

Z80 64 KiB Address Plane · Mapper Ports $FC/$FD · Resident Kernel Page

UZIX カーネルのメモリ構成とプロセス空間の割り当て仕様です。
"Memory plane partitioning isolating the resident kernel from dynamic user process contexts using memory mapper ports."
メモリ領域 (Z80 Address) 常駐内容 (Resident Content) マッパー動作と機能 (Mapper Behavior)
0x0000–0x3FFF (Page 0) ユーザプロセス空間 (Text & Data) マッパーポート 0xFC。プロセス切り替え時にプロセスの物理 RAM セグメントをマッピング。
0x4000–0x7FFF (Page 1) ユーザプロセス空間 (Heap & User Stack) マッパーポート 0xFD。ユーザプロセスの動的メモリ割り当ておよびコールスタック空間。
0x8000–0xBFFF (Page 2) カーネルコードおよび VFS キャッシュ マッパーポート 0xFE。常駐固定セグメント。システムコールハンドラ、スケジューラ、ファイルシステム。
0xC000–0xFFFF (Page 3) カーネルデータ、PCB、I/O バッファ、カーネルスタック マッパーポート 0xFF。常駐固定セグメント。全プロセスの管理テーブル (PCB) および MSX ハードウェア I/O。
02 / Multitasking

2. プロセス管理とプリエンプティブスケジューラ (Preemptive Multitasking)

PCB struct proc · 60Hz Context Switching · Register Frame Stacks

タイマー割り込み（60Hz）によるプリエンプティブコンテキストスイッチとプロセス管理構造です。
"Preemptive scheduling driven by the 60 Hz VDP vertical blanking interrupt, saving full Z80 register states onto process stacks."
PCB フィールド (Field) 型・サイズ (Type) 機能仕様と管理内容 (Role & Definition)
p_pid pid_t (uint16) 一意のプロセス識別子 (PID)。init は PID 1。
p_ppid pid_t (uint16) 親プロセスの PID。終了時に親へ SIGCHLD を配送。
p_status uint8_t プロセス状態 (P_READY, P_RUNNING, P_SLEEP, P_ZOMBIE)。
p_priority int8_t スケジューリング優先度 (-20〜+20)。nice 値により動的補正。
p_page0, p_page1 uint8_t, uint8_t プロセスに割り当てられた物理メモリマッパーセグメント番号 (Page 0/1)。
p_sp uint16_t コンテキストスイッチ時におけるプロセスの退避スタックポインタ (SP)。
p_sigmask uint16_t 保留中シグナルマスク (SIGHUP, SIGINT, SIGKILL, SIGPIPE 等)。
p_files[] struct file*[16] オープン中ファイル記述子配列 (stdin, stdout, stderr, etc.)。
プリエンプティブコンテキストスイッチの手順:
  1. 60Hz VDP 垂直同期割込みが発生。Z80 割込みハンドラが起動。
  2. 実行中プロセスの全レジスタ群（AF, BC, DE, HL, IX, IY, PC および裏レジスタ AF', BC', DE', HL'）をスタックへ PUSH。
  3. スタックポインタ SP をカレントプロセスの p_sp に保存。
  4. スケジューラが実行可能キューから最高優先度の次プロセスを選択。
  5. I/O ポート 0xFC および 0xFD に次プロセスの p_page0, p_page1 を出力し、アドレス空間を瞬時に切り替え。
  6. 次プロセスの p_sp からスタックポインタを復帰し、全レジスタを POP して RETI。
03 / System Calls

3. Unix V7 システムコール規約 (Unix V7 System Call Table)

RST 30H Trapping · POSIX-Compliant File & Process APIs

UZIX カーネルが Z80 上で提供する代表的な Unix V7 システムコール群です。
"POSIX/V7 standard system calls trapped via Z80 software interrupts, exposing fork, execve, pipe, and filesystem controls."
番号 (Call No) システムコール名 C 言語シグネチャ (Signature) 機能仕様 (Functional Specification)
0x02 fork pid_t fork(void) プロセスの複製。親プロセス空間を新規マッパーセグメントへ複製し子プロセスを生成。
0x03 read int read(int fd, void *buf, int nbytes) ファイル記述子からのデータ読み込み（VFS キャッシュバッファ経由）。
0x04 write int write(int fd, const void *buf, int nbytes) ファイル記述子へのデータ書き込み。
0x05 open int open(const char *path, int flags, int mode) パス名を Inode テーブルで解決し、ファイル記述子を返却。
0x06 close int close(int fd) ファイル記述子をクローズし、参照カウントを減算。
0x07 wait pid_t wait(int *status) 子プロセスの終了待機。終了ステータスを取得しゾンビプロセスを解放。
0x0B execve int execve(const char *path, char *const argv[], char *const envp[]) 実行可能バイナリ（UZIX a.out 形式）をプロセス空間にロードして実行開始。
0x0C chdir int chdir(const char *path) プロセスのカレントワーキングディレクトリ Inode を変更。
0x11 brk int brk(void *addr) プロセスのデータセグメント終端（ヒープ境界）を動的に拡張。
0x12 stat int stat(const char *path, struct stat *buf) 指定パスの Inode メタデータ（サイズ、パーミッション、更新日時）を取得。
0x2A pipe int pipe(int fildes[2]) 単方向パイプの作成。メモリバッファを用いたプロセス間通信チャネル。
04 / Filesystem

4. V7 ファイルシステムと Inode 構造 (V7 Filesystem & Inodes)

512-Byte Disk Blocks · Superblock · Multi-Level Direct/Indirect Inodes

512 バイトブロックで構成される UZIX の Inode ベースファイルシステム仕様です。
"Unix Seventh Edition filesystem layout featuring 512-byte disk blocks, superblocks, and direct/indirect inode addressing."
構造体メンバ (Member) 型・サイズ 機能仕様とディスク配置 (Inode Role & Layout)
i_mode uint16_t ファイル種別（通常ファイル、ディレクトリ、文字デバイス、ブロックデバイス、パイプ）およびパーミッション。
i_nlink uint8_t ハードリンク数。0 に達した際にディスクブロックを解放。
i_uid, i_gid uint8_t, uint8_t ファイル所有者およびグループ識別子。
i_size uint32_t ファイルサイズ（バイト長、最大 16 MiB）。
i_addr[0..5] uint16_t[6] 直接ブロックアドレス (Direct Blocks)。最初の 3,072 バイトを直接参照。
i_addr[6] uint16_t 間接ブロックアドレス (Indirect Block)。256 個のデータブロックアドレスを保持するセクタを参照。
i_addr[7] uint16_t 二重間接ブロックアドレス (Double Indirect Block)。大容量ファイル用。
05 / B-MSX Integration

5. B-System B-MSX における UZIX エミュレーション (UZIX in B-MSX Core)

Mapper I/O Ports $FC–$FF · 80-Column Text Engine · Deterministic Clock

B-System ワークベンチ空間上で UZIX のマルチタスクおよび端末シェルを駆動する仕様です。
"B-MSX C99 hardware modeling supporting UZIX memory mapper segment paging and 80-column V9938 terminal emulation."
エミュレーション要素 実装方式 (Implementation Details)
マッパー I/O ポート 0xFC–0xFF C99 完全モデル化。ポート書き込み時に各 16 KiB ページのアドレスポインタテーブルを瞬時に置換し、ゼロオーバーヘッドでプロセス空間をスイッチ。
V9938 80桁コンソール SCREEN 0 (80×24) テキストモードを高速ラスタライズ。ANSI エスケープシーケンスおよび Unix ターミナルコマンドを鮮明に表示。
ストレージ仮想化 UZIX のフロッピーイメージ（720KB）および IDE / SD ハードディスクイメージ（最大 32MB）を仮想ブロックデバイスとしてマウント。
