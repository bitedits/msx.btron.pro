MSX-DOS (Systems)

CP/M 互換 BDOS 呼出規約と MS-DOS FAT ファイルシステムの完全統合、および現代の Nextor 拡張。 "Complete technical specification of MSX-DOS 1/2 and Nextor, detailing INT 21h system calls, FCB/handle file management, FAT12/FAT16 disk structures, and modern storage drivers."
← 基本ソフト目録へ戻る (Systems Index)
Tim Paterson による架け橋と FAT ファイルシステム統合 — MSX-DOS は、MS-DOS の原作者であるティム・パターソン氏らによって開発されました。8 ビット Z80 空間で CP/M 2.2 と完全なシステムコール互換性（アドレス $0005 呼出）を保ちながら、ディスクフォーマットには PC/AT 互換機と直接交換可能な FAT12 を採用。さらに MSX-DOS 2 では階層ディレクトリ、ファイルハンドル、環境変数、および動的メモリマッパー管理が導入され、現代のオープンソース Nextor によって FAT16 大容量 SD カード運用へと進化を遂げました。B-System の B-MSX では、WD2793/MB89311 コントローラエミュレーションを通じて 720KB フロッピーイメージをネイティブ稼働させます。
"Engineered by MS-DOS author Tim Paterson, MSX-DOS bridged the 8-bit CP/M software ecosystem with the IBM PC FAT filesystem standard. Running out of address $0100 in transient program areas, it progressed from FAT12 floppy disks to MSX-DOS 2 directory trees and Albert Beevendorp's FAT16 Nextor kernel. In B-System, the B-MSX core replicates WD2793 floppy controllers for authentic media execution."
01 / BDOS API

1. BDOS システムコール規約 (INT 21h / CALL $0005 API)

CP/M 2.2 Compatibility · MSX-DOS 2 Handles · Memory Mapper Management

レジスタ C に機能コードを格納し、アドレス $0005 へ CALL することで実行されるシステムコール群です。
"Comprehensive register calling conventions for CP/M compatibility, hierarchical file handles, and memory mapper management."
機能番号 (C Reg) 機能名 (Function Name) 入力引数 (Input Registers) 戻り値 (Output Registers) 機能仕様 (Functional Specification)
0x00 Program Terminate なし なし プログラムの実行を終了し、COMMAND.COM へ制御を復帰。
0x01 Console Input なし A = 入力文字コード キーボードから 1 文字入力しエコーバック表示（Ctrl+C 検査あり）。
0x02 Console Output E = 出力文字コード なし コンソール画面へ 1 文字出力。タブ文字は空白に展開。
0x06 Direct Console I/O E (0xFF=入力, その他=出力) A = 入力文字 (入力時) 直接コンソール入出力（エコーバックなし、Ctrl+C 検査なし）。
0x09 Output String DE = '$' 終端文字列番地 なし '$' (0x24) で終わる文字列を画面に出力。
0x0B Console Status なし A (0xFF=文字有, 0x00=空) キーボード入力バッファに文字が存在するかをノンブロッキング検査。
0x0E Select Drive E = ドライブ番号 (0=A, 1=B) A = 総有効ドライブ数 カレントデフォルトドライブを変更。
0x0F Open File (FCB) DE = 未オープン FCB ポインタ A = 0x00 (成功) / 0xFF (失敗) ファイルコントロールブロック (FCB) を用いてファイルをオープン。
0x10 Close File (FCB) DE = オープン済 FCB ポインタ A = 0x00 (成功) / 0xFF (失敗) FCB ファイルをクローズし、ディレクトリエントリの日時・サイズを更新。
0x14 Sequential Read (FCB) DE = FCB ポインタ A = エラーコード (0=成功, 1=EOF) カレントレコードから 128 バイトを DTA バッファへ読み出し。
0x15 Sequential Write (FCB) DE = FCB ポインタ A = エラーコード (0=成功, 1=ディスク満杯) DTA バッファの 128 バイトをカレントレコードへ書き込み。
0x1A Set DTA Address DE = 転送バッファアドレス なし ディスク転送エリア (DTA) のバッファ先頭番地を設定 (デフォルト: $0080)。
0x43 Open File Handle DE = ASCIIZ パス名, A = オープンモード B = ハンドル番号, A = エラー MSX-DOS 2: 階層パスを指定してファイルハンドルを取得。
0x44 Create File Handle DE = ASCIIZ パス名, A = 作成モード, B = 属性 B = ハンドル番号, A = エラー MSX-DOS 2: 新規ファイルを作成しファイルハンドルを取得。
0x45 Close File Handle B = ハンドル番号 A = エラーコード MSX-DOS 2: ファイルハンドルをクローズ。
0x48 Read File Handle B = ハンドル, DE = バッファ, HL = 長さ HL = 実際読込バイト数, A = エラー MSX-DOS 2: ハンドルから指定バイト数を任意メモリへ読み出し。
0x49 Write File Handle B = ハンドル, DE = バッファ, HL = 長さ HL = 実際書込バイト数, A = エラー MSX-DOS 2: ハンドルへ指定バイト数を書き込み。
0x4A Seek File Handle B = ハンドル, A = 基準モード, DE:HL = オフセット DE:HL = 新規ポインタ位置 MSX-DOS 2: ファイルポインタを移動 (0=先頭, 1=現在位置, 2=末尾)。
0x59 Change Directory DE = ASCIIZ ディレクトリパス A = エラーコード MSX-DOS 2: カレントワーキングディレクトリを変更 (CHDIR)。
0x6B Get Environment Item HL = 変数名ポインタ, DE = 値バッファ, B = 長さ A = エラーコード MSX-DOS 2: 環境変数（PATH, PROMPT 等）の値を取得。
02 / FAT Layout

2. ファイルシステム構造 (FAT12 & Nextor FAT16 Architecture)

Boot Sector BPB · 12-bit Packing · Root Directory Entry (32 Bytes)

標準フロッピーディスク (FAT12) および Nextor 大容量ストレージ (FAT16) のセクタ配置仕様です。
"Silicon disk layout defining the BIOS Parameter Block (BPB), 12-bit cluster packing, and 32-byte directory entries."
セクタ領域 (Sector Region) 標準 2DD フロッピー (FAT12) Nextor 大容量区画 (FAT16) 機能と構造 (Functional Role)
ブートセクタ (Boot Sector) LBA 0 (512 バイト) LBA 0 (MBR) / パーティション LBA 0 BPB (BIOS Parameter Block)、クラスタサイズ、FAT数、ブートコード。
FAT テーブル (FAT1 & FAT2) LBA 1〜6 (3セクタ × 2部) クラスタ数に応じた可変セクタ数 FAT12 は 1.5 バイト（12ビット）/クラスタ。FAT16 は 2 バイト（16ビット）/クラスタ。
ルートディレクトリエントリ LBA 7〜13 (112 エントリ固定) 可変 (通常 512 エントリ固定) 各 32 バイトのファイル記述子（ファイル名 8.3、属性、日時、開始クラスタ、サイズ）。
データクラスタ領域 LBA 14〜1439 (713 クラスタ) 最大 65,524 クラスタ (最大 2GB/区画) 実ファイルデータおよびサブディレクトリ（DOS 2）を格納。
32 バイト ディレクトリエントリ構造 (Directory Entry Format):
  • +0x00..+0x07: ファイル主名 (ASCII 8文字、スペース埋め)。先頭 0xE5 は削除済、0x00 は未割当終端。
  • +0x08..+0x0A: 拡張子 (ASCII 3文字、例: "COM", "BAS")。
  • +0x0B: 属性バイト (Bit 0: 読取専用, Bit 1: 隠し, Bit 2: システム, Bit 3: ボリュームラベル, Bit 4: サブディレクトリ, Bit 5: アーカイブ)。
  • +0x16..+0x17: 最終更新時刻 (Bit 15–11: 時 0–23, Bit 10–5: 分 0–59, Bit 4–0: 秒/2 0–29)。
  • +0x18..+0x19: 最終更新日付 (Bit 15–9: 年 1980年起点, Bit 8–5: 月 1–12, Bit 4–0: 日 1–31)。
  • +0x1A..+0x1B: 開始クラスタ番号 (16ビット、FAT テーブルの探索インデックス)。
  • +0x1C..+0x1F: ファイルサイズ (32ビット符号なし整数、最大 4 GiB、FAT12/16 実効値)。
03 / Disk Driver

3. ディスクコントローラと Disk ROM ベクタ (Disk Driver & FDC Controller)

WD2793 / MB89311 FDC · Disk ROM Jump Table · Memory Map

フロッピーディスクコントローラ (FDC) および Disk ROM が提供する下位ドライバベクタ群です。
"Low-level driver entry points implemented within Disk ROM firmware, mediating hardware I/O with floppy controllers."
ROM アドレス ベクタ名 (Identifier) 引数・レジスタ (Registers) 機能仕様 (Functional Specification)
$4010 DSKIO F (Carry=書込, NC=読出), A = ドライブ, B = セクタ数, C = メディア記述子, DE = 論理セクタ番号, HL = メモリバッファ ディスクセクタの物理リード／ライト。エラー時は Carry フラグとともに A レジスタにエラー種別を返却。
$4013 DSKCHG A = ドライブ, B = メディア記述子 ディスク交換状態の検査。戻り値 B = 1 (未交換), 0 (不明), -1 (交換済)。
$4016 GETDPB A = ドライブ, HL = DPB 格納バッファ ドライブパラメータブロック (DPB) を構築してバッファに取得。
$4019 CHOICE 戻り値: HL = 選択肢文字列ポインタ ディスクフォーマット時の選択肢メニュー文字列を取得。
$401C DSKFMT A = ドライブ, D = 選択肢番号, HL = ワークバッファ ディスクの物理フォーマットおよびトラックベリファイを実行。
04 / C-BIOS & DOS Mapping

4. C-BIOS / B-MSX マッピング互換トランポリン機構 (C-BIOS & DOS Mapping Layer)

dsk.c · slots.c · Port $D4 Trapping · Upper RAM Trampolines · TPA Switching

B-System B-MSX 公式標準ファームウェアである C-BIOS 環境下で、プロプライエタリな Disk BASIC を介さずに MSX-DOS / TPA を稼働させるマッピングレイヤ仕様です。
"Deterministic C99 compatibility layer bridging C-BIOS with MSX-DOS, featuring port $D4 BDOS trapping, Page 0 TPA RAM vector initialization, and upper RAM interrupt trampolines."
互換機構 (Mechanism) 技術仕様と C99 / Z80 トランポリン動作 (Technical Specification & Trampoline)
ポート $D4 BDOS トラップ
dsk.c / slots.c 		FAT12 ダイレクト DMA 展開:
slots.c は C-BIOS ディスク ROM パディング領域（$44C0）へ OUT (D4), A / RET を注入。機能 0x0F（オープン）および 0x27（ランダム読出）をここへ接続。Z80 がポート $D4 を叩くと tronmsx.c がトラップし、dsk_bdos() がメモリ内 FAT12 構造から MSXDOS.SYS や .COM を直接 TPA へ DMA 展開。
Page 0 TPA RAM 切替
0x0000–0x3FFF 		全ページ RAM マッピング (Slot 3):
DOS プログラム起動時、Page 0 を C-BIOS ROM からメイン RAM へ切り替え。TPA $0100 にプログラムを配置し、低位番地に必須ベクタを構築：
  • $0000: JP $0000 (ウォームブート)
  • $0005: JP $F200 (上位 RAM BDOS ゲート)
  • $0030: JP $F230 (RST $30 CALLF トランポリン)
  • $0038: JP $F210 (RST $38 IM 1 VBLANK トランポリン)
VBLANK IM 1 トランポリン
$F210 (27 バイト) 		Page 0 RAM 環境での垂直同期割込み解決:
Page 0 が TPA RAM になっている間、BIOS 割込みハンドラを直接呼べないため、上位 RAM（$F210）の 27 バイトトランポリンが一時的に PPI ポート A（$A8）を Slot 0（C-BIOS ROM）へ切り替え、ROM の KEYINT（$0038）を実行後に TPA RAM へ復元。
MSXDOS.SYS パッチ
$50A9 ($10A9) 		未定義パディング命令の修正:
MSXDOS.SYS が Page 0 ベクタ構築後に呼ぶ $50A9 番地が C-BIOS ディスク ROM では 0xFF（RST $38）となりクラッシュするため、slots.c が 0x10A9 を RET (0xC9) へ動的パッチ。
BSAVE ($FE) vs DOS .COM
dsk.c 形式判別 		バイナリ形式の自動嗅知:
ディスク内ファイルの先頭バイトが 0xFE の場合、Disk BASIC BSAVE 形式と判別し、Page 0 に C-BIOS を維持したまま BLOAD 空間へロード。それ以外は $0100 へ配置し DOS モードとして起動。
05 / B-MSX Integration

5. B-System B-MSX におけるフロッピーエミュレーション (FDD Subsystem in B-MSX)

WD2793 Silicon Simulation · Raw 720KB Disk Images · HC-95 FDD Support

B-System ワークベンチ空間で MSX-DOS を稼働させるためのフロッピーディスク仮想化仕様です。
"Silicon-level WD2793 controller simulation in B-MSX handling 720 KiB raw disk image files and direct DOS boot sequences."
コンポーネント エミュレーション方式 (Methodology) 技術詳細 (Technical Architecture)
WD2793 コントローラ C99 レジスタレベルステートマシン コマンドレジスタ（Seek, Step, Read Sector, Write Sector）およびステータスレジスタ（CRCエラー、Indexパルス）の完全シミュレーション。
フロッピーディスクイメージ 720 KiB RAW イメージ (.dsk) 両面・80トラック・9セクタ/トラック・512バイト/セクタの標準 2DD ジオメトリ（総 1,440 セクタ）を仮想ドライブへ直接マウント。
