tronMSX (Emulators)

B-System に組み込まれた、Hitachi HD64180 / R800 / Z80 確定性実行・ゼロコピー描画・44.1 kHz PCM 合成を備えた純 C99 MSX2+ コア。 "Technical specification of tronMSX, the embedded cleanroom C99 MSX2+ core within B-System. Built under strict NASA/JPL rules with zero dynamic allocation, featuring the newly actualized Hitachi HD64180 CPU chip (hd64180.c) alongside ASCII R800 and Z80 pipelines."
← 摸擬目録へ戻る (Emulators Index)
確定性とクリーンルームの結晶 — tronMSX は、BTRON 3.20（B-System）のウィンドウ空間上で直接動作する MSX2+ エミュレーションコアです。NASA/JPL「Power of Ten」規則に厳格に従い、ブート後の動的ヒープ確保（malloc）を完全に禁止し、全ループを有界（Bounded）に抑え、静的メモリ空間のみで稼働します。新たに統合された Hitachi HD64180 コア（hd64180.c） により、日立 HC-90 / HC-95 ワークステーションの 6.144 MHz 拡張命令セット（MLT, IN0/OUT0, TST, PRT タイマー）を完全再現。描画フレームバッファは BTRON ウィンドウマネージャのプレーンへゼロコピー転送され、音響は VirtIO-Sound / SDL2 へ 44.1 kHz 16-bit PCM として送出されます。
"tronMSX is an uncompromising cleanroom C99 MSX2+ engine embedded inside B-System. Adhering strictly to NASA/JPL Power of Ten rules, it forbids post-boot heap allocations and enforces bounded execution times. The architecture now incorporates the full Hitachi HD64180 CPU emulation unit (hd64180.c), executing 8-bit multiplies, internal I/O, MMU registers, and PRT reload timers for Hitachi HC-90/95 workstations without external dependencies."

1. C99 コア構造とシリコンチップ分割 (Silicon Core Units)

Modular Chip Emulation · Static Struct Allocation · BTRON Kernel Integration

tronMSX を構成する C99 純実装シリコンチップモジュールの一覧です。
"Modular organization of C99 chip emulation cores, isolating CPU, VDP, sound chips, FDC, and 3D geometry pipeline into deterministic units."
ソースファイル (Source Module) エミュレーション対象チップと技術仕様 (Hardware Target & Silicon Architecture)
hd64180.c / hd64180.h
新世代日立 CPU コア 		Hitachi HD64180 (6.144 MHz): 日立 HC-90 / HC-95 向け CPU。8 ビット乗算（MLT BC/DE/HL/SP）、内部 I/O レジスタ（IN0/OUT0）、非破壊論理積（TST/TSTIO）、低消費電力スリープ（SLP）、プログラマブル・リロードタイマ（PRT ch0/1）、および MMU レジスタ群（CBAR, CBR, BBR, ICR）を完全エミュレート。
z80.c / z80.h
標準 Z80 CPU コア 		Zilog Z80A (3.58 MHz): 全非公開命令（Undocumented opcodes）、フラグ計算、割込みモード IM1/IM2、リフレッシュレジスタ（R）の完全エミュレーション。zexall テスト適合。
r800.c / r800.h
turbo R RISC 風 CPU 		ASCII R800 (28.6 MHz 相当): MSX turbo R 向けプロセッサ。16 ビット符号なしハードウェア乗算命令（MULUB 8×8→16, MULUW 16×16→32）およびパイプラインバス調替。
v9938.c / vdp.c
ヤマハ VDP レンダラ 		TMS9918A / V9938 / V9958: SCREEN 0〜8、VRAM 128 KiB アクセス、カラーパレット、32 枚スプライトプレーン、ハードウェアコマンド（HMMV, LMMV, HMMC, YMMM, LINE）。標準ポート 0x98–0x9B およびワークステーション 0x88–0x8B 両対応。
psg.c / audio.c
PSG 音響合成ユニット 		AY-3-8910 / YM2149: 1,789,772 Hz クロック、16 段階対数減衰（左5ビットシフト）、14 Hz 直流阻止ハイパスフィルタ、VirtIO-Sound 44.1 kHz 16-bit PCM 送出。
opll.c / y8950.c
FM 音源合成ユニット 		YM2413 (MSX-MUSIC) & Y8950 (MSX-AUDIO): 2 オペレータ 9ch FM 変調、128 段 × 0.375 dB 減衰器、6.1 Hz ビブラート、3.7 Hz トレモロ。
pcm.c
turboR PCM サウンド 		MSX turbo R PCM: 15,700 Hz サンプリング、ポート 03H/02H スルーリミッタ制御（最大 48 段/刻み）、8 ビット DAC 出力。
slots.c / bios.c
スロット制御・C-BIOS 		PPI 8255 & Subslots: 基本スロット（ポート 0xA8）、拡張サブスロット（0xFFFF 反転）、および MegaROM マッパー（Flat, Konami, ASCII 8K/16K 最大 4 MiB）。C-BIOS 自動装填。
dsk.c
フロッピーディスク仮想化 		WD2793 / MB89311 FDC: 720 KiB RAW ディスクイメージ（2DD, 80 トラック 9 セクタ）のステートマシンシミュレーション。HC-95 FDD ネイティブサポート。
geo3d.c
3D 幾何学アクセラレータ 		Geo3D パイプライン: 16-bit 固定小数点 3 次元マトリクス乗算、同次座標クリッピング、V9938 SCREEN 7/8 高速ポリゴンラスタライザ。
02 / HD64180 Silicon

2. 日立 HD64180 チップアーキテクチャ (Hitachi HD64180 Core Specification)

hd64180.c Implementation · 64-Byte Internal I/O · PRT Timers · MMU Paging

../btron/src/emulators/msx/hd64180.c に実装された HD64180 内部 I/O レジスタおよびタイマー制御構造です。
"Hardware registers and state machine structures governing the 64-byte internal I/O space, MMU base mapping, and dual PRT reload timers."
レジスタ / 構造体メンバ I/O アドレスと機能仕様 (Register Function & Paging Behavior)
ICR (Interrupt Control)
Internal Reg 0x3F 		I/O ベースアドレス設定: Bit 7–6 が内部 64 バイト I/O レジスタブロックの先頭アドレスを指定（0x00, 0x40, 0x80, 0xC0）。hd64180_is_internal_io() により外部ポートアクセスと瞬時弁別。
CBAR (Common/Bank Area)
Internal Reg 0x3A 		MMU 領域境界設定: 上位 4 ビット（CA）が Common Area 1 の開始境界アドレス、下位 4 ビット（BA）が Bank Area の開始境界アドレスを設定。リセット時デフォルト値は 0xF0（Common Area = F000H–FFFFH）。
CBR / BBR (Base Registers)
Internal Reg 0x38 / 0x39 		MMU 物理アドレスベース: Common Area Base Register (CBR) および Bank Area Base Register (BBR)。Z80 の 64 KiB 論理空間を 1 MiB の物理空間へ線形マッピング。
TMDR0 / TMDR1
Reg 0x0C–0x0D / 0x14–0x15 		16 ビットタイマデータレジスタ: PRT (Programmable Reload Timer) チャンネル 0 および 1 のダウンカウンタ現在値。CPU クロック 20 分周（または 10 分周）で減算カウント。
RLDR0 / RLDR1
Reg 0x0E–0x0F / 0x16–0x17 		16 ビットタイマリロードレジスタ: TMDR がアンダーフロー（0x0000）に達した際に自動再装填されるプリセット値。定期タイマー割込みの生成基盤。
TCR (Timer Control)
Internal Reg 0x10 		タイマ制御レジスタ: TIF0 / TIF1（タイマ割込みフラグ、0 書込でクリア）、TIE0 / TIE1（割込み許可）、TDE0 / TDE1（ダウンカウント動作許可）。
03 / Opcode Extensions

3. HD64180 拡張命令セット実装 (Extended Instruction Set)

0xED Prefix Extensions · MLT 8-bit Multiply · IN0/OUT0 · TST · SLP

hd64180_check_ext() によりディスパッチされる、Z80 に対する拡張機械語命令仕様です。
"Deterministic emulation of HD64180-specific opcodes trapped under the ED prefix, detailing cycle penalties and register side effects."
機械語コード (Opcode) ニーモニック (Mnemonic) 所要サイクル 演算動作とハードウェア仕様 (Operation & Flags)
ED 4C MLT BC 17 サイクル 8ビット符号なし乗算: BC = B × C。フラグ変化なし。
ED 5C MLT DE 17 サイクル 8ビット符号なし乗算: DE = D × E。フラグ変化なし。
ED 6C MLT HL 17 サイクル 8ビット符号なし乗算: HL = H × L。フラグ変化なし。
ED 7C MLT SP 17 サイクル 8ビット符号なし乗算: SP = SPh × SPl。スタックポインタ各バイトを乗算。
ED 00..38 (m) IN0 r, (m) 12 サイクル 内部ポート m からレジスタ r へ直接入力。S, Z, H=0, P/V (パリティ), N=0 を更新。
ED 01..39 (m) OUT0 (m), r 13 サイクル レジスタ r の値を内部ポート m へ直接出力。
ED 04..3C TST r 7 サイクル 非破壊論理積: A & r。結果を保持せず、S, Z, H=1, P/V, N=0, C=0 を更新。
ED 34 TST (HL) 13 サイクル 非破壊論理積: A & (HL)。メモリ内容と A の論理積をテスト。
ED 64 (imm) TST imm 9 サイクル 非破壊論理積: A & imm。即値バイトと A の論理積をテスト。
ED 74 (imm) TSTIO imm 12 サイクル ポート論理積: (Port C) & imm。C レジスタが示すポートの入力と即値をテスト。
ED 76 SLP 8 サイクル スリープモード移行: CPU クロックを停止し、外部割込み（INT0/1/2）の到来まで待機。
ED 83 / 93 OOTIM / OOTIMR 15 サイクル 内部ブロック転送出力: OUT0 (C), (HL); HL++; B--。OOTIMR は B=0 まで反復実行。
04 / Verification

4. NASA/JPL Power of Ten 検証と確定性 (Verification & Determinism)

Zero Heap Allocations · Bounded Execution Loops · Headless Automated Testing

航空宇宙・高信頼性システム工学規約に準拠した tronMSX の堅牢性メトリクスです。
"High-assurance software engineering compliance under NASA/JPL rules, guaranteeing bounded execution times and zero heap faults."
NASA/JPL 設計原則 tronMSX C99 コアにおける具現化手法 (C99 Engineering Practice)
規則 1: 制御フローの単純化 goto、setjmp、longjmp の完全排除。全サブルーチンの呼び出し階層は最大 4 段以内に制限。
規則 2: すべてのループに固定上限 CPU 命令実行、VDP コマンドラスタライズ、音響バッファ転送の全ループに固定最大イテレーション数を設定。無限ループを物理遮断。
規則 3: 初期化後のヒープ確保禁止 ブート完了後の malloc / calloc / free 呼出を完全禁止。全状態（hd64180_state_t, VRAM 128KB, ワークエリア）を静的構造体として事前割当。
規則 4: 関数の長さを 60 行以内に制限 各関数を 1 画面に収まる長さに保ち、サイクロマティック複雑度を低減。
規則 5: ポインタ検証とアサーション 全パブリック API（hd64180_init, hd64180_step 等）の先頭で非 NULL ポインタを厳格検証。不正メモリアクセスを即時抑止。
