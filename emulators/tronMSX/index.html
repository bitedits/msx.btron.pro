tronMSX (Emulators)

B-System に組み込まれた、全シリコンモジュール確定性実行・ゼロコピー描画・44.1 kHz PCM 合成を備えた純 C99 MSX2+ コア。 "Definitive technical specification of tronMSX, the embedded cleanroom C99 MSX2+ core within B-System. Fully actualized across all silicon source modules (z80, r800, hd64180, v9938, psg, opll, y8950, pcm, scc, slots, dsk, geo3d, and msx_app) under strict NASA/JPL Power of Ten rules."
← 摸擬目録へ戻る (Emulators Index)
全シリコンチップの確定性 C99 統合 — tronMSX（B-MSX Rev 1.05）は、BTRON 3.20（B-System）のウィンドウ空間上で直接動作する、外部共有ライブラリ非依存の確定論的 MSX2+ / turbo R / 日立ワークステーション エミュレーションコアです。航空宇宙水準の NASA/JPL「Power of Ten」規則に厳格に従い、ブート完了後の動的ヒープ確保（malloc）を完全に禁止し、全ループを有界（Bounded）に抑え、静的メモリ構造体のみで稼働します。CPU、VDP、音源、スロット、ディスク、3D 幾何学アクセラレータに至る全ソースモジュールの詳細を以下に完全公開します。
"tronMSX is an uncompromising cleanroom C99 MSX2+ engine embedded inside B-System. Adhering strictly to NASA/JPL Power of Ten rules, it forbids post-boot heap allocations and enforces bounded execution times across all hardware modules. Every silicon unit—CPU, VDP, sound chips, slot bus, FDC, and 3D geometry engine—operates deterministically without third-party dependencies."

02 / CPU Cores

2. CPU サブシステム解体 (CPU Subsystem: z80, r800, hd64180)

Z80A · ASCII R800 · Hitachi HD64180 · zexall Conformance

3 大プロセッサコア（Z80, R800, HD64180）の実装構造と機械語拡張仕様です。
"Deep dive into the heterogeneous CPU emulation engines covering instruction decoding, M1 cycles, hardware multipliers, and MMU paging."
CPU モジュール (Module) 内部アーキテクチャと C99 実装詳細 (Internal Architecture & C99 Details)
z80.c / z80.h
Zilog Z80A (3.58 MHz) 		完全命令セットとサイクル正確性:
全 256 主命令に加え、プレフィックス CB, ED, DD, FD, DDCB, FDCB を完全網羅。パリティフラグ計算は 8 ビット XOR ルックアップ、M1 サイクルウェイト、非公開命令（IXH, IXL, SLL 等）、および割込みモード IM0/1/2 を忠実に再現。zexall.c ハーネスにより Zilog 公式挙動テストに全数合格。
r800.c / r800.h
ASCII R800 (28.6 MHz 相当) 		16 ビットハードウェア乗算と RISC 風パイプライン:
MSX turbo R に搭載された 16 ビットプロセッサ。新設された 2 種の符号なし乗算命令を C99 で直値計算：
  • MULUB A, B (ED C1): 8 ビット乗算 HL = A × B (17 サイクル)。
  • MULUW HL, BC (ED C3): 16 ビット乗算 DE:HL = HL × BC (17 サイクル)。
乗算オーバーフローはフラグに反映されず、バス調替（T9769C）との連携で turbo R の 16 ビット DMA を高速実行。
hd64180.c / hd64180.h
Hitachi HD64180 (6.144 MHz) 		内部 I/O レジスタ・MMU・8 ビット乗算 (日立 HC-90/95):
hd64180_state_t により 64 バイト内部 I/O を管理。ICR (0x3F) によるベースポート動的切替、CBAR (0x3A) / CBR (0x38) / BBR (0x39) による 1 MiB 物理アドレス MMU 変換、および 2ch PRT タイマー（TMDR0/1, RLDR0/1, TCR）。
拡張命令群：MLT BC/DE/HL/SP（8ビット乗算 17サイクル）、IN0 / OUT0（内部ポート直接 I/O）、TST / TSTIO（非破壊論理積）、SLP（スリープ 8サイクル）、OOTIM / OOTIMR（ブロック内部出力）。
03 / Video Subsystem

3. ビデオ表示および描画エンジン (Video Subsystem: v9938.c, vdp.c)

Yamaha V9938/V9958 · 128 KiB VRAM · Hardware Blitter Engine

MSX2/MSX2+/turbo R の描画を担う VDP コアおよびハードウェアアクセラレーション仕様です。
"Rasterization architecture for Yamaha V9938/V9958 processors, detailing VRAM layouts, palette tables, and hardware blitter commands."
VDP 描画機能 (Subsystem) ハードウェア仕様と C99 レンダリング実装 (Implementation Details)
VRAM 空間と多重画面モード 128 KiB VRAM を静的配列として確保。SCREEN 0（40/80 桁テキスト）、SCREEN 1（32 桁テキスト）、SCREEN 2（高解像度グラフィック）、SCREEN 3（マルチカラー）、SCREEN 4（スプライト 2）、SCREEN 5（256×212 16色）、SCREEN 6（512×212 4色）、SCREEN 7（512×212 16色）、SCREEN 8（256×212 256色RGB）、および V9958 自然画 SCREEN 10/11/12（YJK/YAE）をピクセルパーフェクト描画。
VDP コマンドエンジン 描画負荷をオフロードするハードウェアコマンド群を C99 で完全実装：
  • HMMV / LMMV: 高速矩形塗りつぶし・論理演算塗りつぶし。
  • HMMC / LMMC: CPU から VRAM への高速バーストデータ転送。
  • YMMM / HMMM: VRAM 内部矩形コピー（高速スクロール）。
  • LINE: ブレゼンハムのアルゴリズムに基づくハードウェア線分描画。
  • SRCH: カラー境界探索（ペイントアルゴリズム用）。
パレットとスプライト面 16 本の 9 ビットパレットレジスタ（GRB 各 3 ビット、512 色中 16 色同時発色）。32 枚のスプライトプレーン（8×8 / 16×16、拡大表示対応）、走査線あたり 8 枚制限、第 5 スプライトフラグ（ST_5S）および衝突検出フラグ（ST_C）を正確にモデリング。
二重 I/O ポート対応 標準ポート 0x98–0x9B（データ、ステータス/レジスタ、パレット、間接レジスタ）に加え、ワークステーション（HC-90/95、HC-95 FDD 等）で採用されたエイリアスポート 0x88–0x8B の双方へシームレスに応答。
04 / Sound Subsystem

4. 音源合成サブシステム (Sound Subsystem: psg, opll, y8950, pcm, scc)

AY-3-8910 · YM2413 OPLL · Y8950 · turboR PCM · Konami SCC

PSG、FM 音源、PCM、および SCC 波形メモリ音源の C99 リアルタイム合成仕様です。
"Audio synthesis engines producing deterministic 44.1 kHz 16-bit PCM streams across PSG, OPLL FM, SCC wavetables, and turbo R PCM."
音源チップ (Sound Chip) 物理仕様・合成アルゴリズム・PCM 送出規約 (Synthesis Architecture)
psg.c / audio.c
AY-3-8910 / YM2149 		整数固定小数点 PSG 合成 (1,789,772 Hz):
3 つのトーンジェネレータ（f = PSG_HZ / (16·TP)）、17 ビット擬似乱数シフトレジスタ（初期値 0x0ACE、f = PSG_HZ / (16·NP)）、および 32 ステップエンベロープシーケンサ（YM2149 規約）。16 段階対数音量テーブル（0〜8160）を適用し、14 Hz ハイパスフィルタで直流成分を阻止。VirtIO-Sound へ 735 サンプル/フレーム（60Hz）送出。
scc.c
Konami SCC / SCC+ 		波形メモリ音源 (5 チャンネル):
0x9800–0x987F に配置された 5 本の 32 バイト波形 RAM（32 サンプル/周期）。周波数分周カウンタ f = 3579545 / (32·period) により波形テーブルを巡回参照。周期 9 未満の超音波設定時は無音化。
opll.c / fm_int.h
Yamaha YM2413 (MSX-MUSIC) 		2 オペレータ 9ch FM 音源合成:
I/O ポート 0x7C/0x7D。15 種類のクリーンルーム内蔵パッチスケッチと 1 ユーザー音色。リズムモード選択時はチャンネル 6〜8 がバスドラム、スネア、タム、シンバル、ハイハットの 5 パーカッションへ転換（各リズム音声を 2 回重ねる +6 dB ブースト仕様）。128 段階 × 0.375 dB 減衰器。
y8950.c
Yamaha Y8950 (MSX-AUDIO) 		FM-AUDIO & ADPCM-B:
I/O ポート 0xC8/0xC9。9 チャンネル FM 合成に加え、ADPCM 音声サンプリング/再生レジスタを保持。
pcm.c
MSX turbo R PCM 		15,700 Hz 8-bit DAC:
I/O ポート 0xA4/0xA5。ポート 03H は次刻み出力、02H は即時出力。刻みあたり最大 48 段階のスルーリミッタを介して 44,100 Hz PCM バッファへアップサンプリング（0xFF 出力時は +8128）。

5. バス調停・スロット・外部記憶サブシステム (Bus & Storage: slots, dsk, rtc)

PPI 8255 · Subslots · MegaROM Mappers · WD2793 FDC · Ricoh RP5C01

スロット階層、MegaROM バンク切替、フロッピー仮想化、および周辺 LSI の仕様です。
"Bus multiplexing architectures handling primary slots, secondary subslots, MegaROM bank sniffers, and raw disk image FDC controllers."
サブシステム (Module) バス制御プロトコルとハードウェア動作 (Bus Control Architecture)
slots.c / ppi.c
スロット多重化 & MegaROM 		スロット階層とマッパー嗅知:
PPI 8255 ポート A（0xA8）による 4 ページの基本スロット選択（Slot 0: BIOS, Slot 1: Cart A, Slot 2: Cart B, Slot 3: RAM）。各基本スロットの 0xFFFF に配置された二次スロットレジスタ（反転リード/ライト）。
カートリッジマッパー：Flat 32K、ASCII 8K（0x6000–0x7800）、ASCII 16K（0x6000/0x7000）、Konami（8K バンク）、Konami SCC を自動検出。最大 4 MiB までの MegaROM を動的バンキング。
dsk.c
WD2793 / MB89311 FDC 		フロッピーコントローラステートマシン:
720 KiB RAW ディスクファイル（2DD、両面 80 トラック、9 セクタ/トラック、512 バイト/セクタ）を仮想ドライブ A/B にマウント。シーク、ステップ、セクタ読込、セクタ書込コマンドを C99 ステートマシンで正確に模倣。HC-95 FDD ネイティブサポート。
s1985.c / t9769c.c / rtc.c
MSX エンジン & RTC 		MSX エンジン LSI と時計:
Yamaha S1985（MSX2 用システムコントローラ）、Toshiba T9769B/C（MSX2+/turbo R 用統合 LSI、クロック切替とスロット制御）。Ricoh RP5C01 リアルタイムクロック（I/O ポート 0xB4/0xB5、4 ビット 26 レジスタバンク、不揮発性 RAM 領域）。
06 / Geo3D

6. Geo3D 3次元幾何学コプロセッサ (Geo3D Geometry Accelerator: geo3d.c)

Fixed-Point 3D Pipeline · muldiv Algorithm · Cohen-Sutherland Clipping

Tang Nano 20K FPGA や B-System 上で 3D ゲーム（Neon Revenant, Night Raven）を駆動する演算パイプラインです。
"Real-time 3D geometry pipeline performing 16-bit fixed-point matrix transforms, homogeneous clipping, and polygon rendering."
幾何学演算ステージ アルゴリズム設計と C99 最適化 (Algorithmic Architecture)
libgcc 非依存 64 ビット muldiv ベアメタルおよび PS2 実行環境において libgcc の __divdi3（64 ビット除算ルーチン）呼び出しを完全排除。シフト、比較、減算のみで構成されるカスタム 64 ビット muldiv(a, b, c) = (a * b) / c をインライン展開。
コーエン・サザーランド同次クリッピング 視体積外部のポリゴン頂点を高速除外。4 ビットアウトコード（INSIDE, LEFT, RIGHT, BOTTOM, TOP）を用い、画面境界における線分交点を高速交差計算。
V9938 SCREEN 7/8 ラスタライザ連携 投影変換された頂点座標を V9938 の LINE および HMMV ハードウェアコマンドへダイレクトパイプライン投入。Z80 の負荷を極小化し、30〜60 fps の 3D ワイヤーフレーム/ポリゴン描画を実現。
07 / GUI & App Integration

7. B-System GUI 統合とフレーム実行 (B-System GUI Integration: msx_app.c)

Fast-Forward Skipping · Zero-Copy Framebuffer · Dynamic Machine Sniffing

B-System ワークベンチ空間と tronMSX を結ぶ、ウィンドウマネージャ統合レイヤ仕様です。
"Workbench window integration handling event routing, cascade menus, fast-forwarding, and direct framebuffer compositing."
統合機能 (Feature) B-System ワークベンチ連携動作 (Workbench Behavior)
早送り (Fast-Forward) msx_app_fast_forward(int frames) により、C-BIOS 初期化やハードウェア診断待機（450〜900 フレーム）を描画遅延なしで瞬時スキップ。ゲームタイトル画面へ 0 秒で到達。
ゼロコピー GDEV 描画 VDP の 256×212 ピクセルバッファから B-System の GDEV グラフィックプレーンへ直接ダイレクトスケーリング転送。中間メモリコピーを完全排除。
機械自動嗅知 (Machine Sniffing) 装填された ROM カートリッジの容量・シグネチャを走査し、MSX1 (TMS9918)、MSX2 JP (V9938)、MSX2+ (V9958)、turbo R (R800)、および日立 HC-90 / HC-95 (HD64180) の最適マシン構成を自動展開。
08 / Verification

8. NASA/JPL Power of Ten 検証と確定性 (Verification & Determinism)

Zero Heap Allocations · Bounded Execution Loops · Headless Automated Testing

航空宇宙・高信頼性システム工学規約に準拠した tronMSX の堅牢性メトリクスです。
"High-assurance software engineering compliance under NASA/JPL rules, guaranteeing bounded execution times and zero heap faults across all modules."
NASA/JPL 設計原則 tronMSX C99 コアにおける具現化手法 (C99 Engineering Practice)
規則 1: 制御フローの単純化 goto、setjmp、longjmp の完全排除。全サブルーチンの呼び出し階層は最大 4 段以内に制限。
規則 2: すべてのループに固定上限 CPU 命令実行、VDP コマンドラスタライズ、音響バッファ転送の全ループに固定最大イテレーション数を設定。無限ループを物理遮断。
規則 3: 初期化後のヒープ確保禁止 ブート完了後の malloc / calloc / free 呼出を完全禁止。全状態（s_cpu, g_hd64180_state, VRAM 128KB, ワークエリア）を静的構造体として事前割当。
規則 4: 関数の長さを 60 行以内に制限 各関数を 1 画面に収まる長さに保ち、サイクロマティック複雑度を低減。
規則 5: ポインタ検証とアサーション 全パブリック API（hd64180_init, z80_step, v9938_cycle 等）の先頭で非 NULL ポインタを厳格検証。不正メモリアクセスを即時抑止。
