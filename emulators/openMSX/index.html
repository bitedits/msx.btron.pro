究極の精度への到達 — openMSX は、単にソフトウェアを動かすことではなく、実機シリコンの物理的挙動を忠実に再現することを目指して設計されています。VDP のラスタースキャン走査、スプライト走査線ドロップアウト、および Z80 の M1 サイクル・ウェイトステートがサイクル単位で同期。外部プロセスから Tcl ソケットを通じてマシン状態を完全制御できるため、CI（継続的インテグレーション）テストに不可欠です。 "openMSX establishes the global gold standard for cycle-accurate MSX virtualization. By synchronizing scanline raster progression, waitstates, and slot switching, it ensures absolute fidelity. Its Tcl control socket permits external build harnesses to run headless regression tests."
01 / XML

1. XML 機体構成スキーマ (XML Machine Definition)

Declarative Silicon Topologies · Slot Nesting

openMSX において機体を定義する宣言的 XML の構造です。
"Structure of declarative openMSX machine XML files organizing devices, quartz crystal frequencies, and nested slot structures." 
<!-- openMSX マシン構成宣言例 (Sony HB-F900 抜粋) -->
<msxconfig>
  <info>
    <manufacturer>Sony</manufacturer>
    <code>HB-F900</code>
    <type>MSX2</type>
    <region>jp</region>
  </info>

  <devices>
    <PPI id="ppi">
      <io base="0xA8" num="4"/>
      <keyboard_type>jp_ansi</keyboard_type>
    </PPI>

    <VDP id="VDP">
      <version>V9938</version>
      <vram>128</vram>
      <io base="0x98" num="4" type="O"/>
      <io base="0x98" num="2" type="I"/>
    </VDP>

    <primary slot="3">
      <secondary slot="1">
        <MemoryMapper id="Main RAM">
          <size>256</size>
        </MemoryMapper>
      </secondary>
    </primary>
  </devices>
</msxconfig>
02 / Tcl

2. Tcl 制御ソケットと自動化 (Tcl Automation)

Headless Testing · Symbol Inspection

Unix ドメインソケットまたはパイプ経由で openMSX を遠隔操作する主要コマンドです。
"Key Tcl commands controlling headless execution, symbol loading, and frame capture via control sockets."
Tcl コマンド (Command) 引数 (Arguments) 機能仕様と自動化における用途
carta <file> ROM パス カートリッジスロット A に指定 ROM を即座に挿入
reset なし 仮想マシンをハードウェアリセット
debug set_bp <addr> アドレス (0x0000–0xFFFF) 指定アドレスへの実行到達時にブレークポイント停止
reverse::go_back <t> 秒数 (例: 5) 指定秒数だけ過去の実行状態へ巻き戻し (タイムトラベル)
screenshot <file> 出力 PNG パス 現在の VDP フレームバッファをピクセル完全な画像として保存
